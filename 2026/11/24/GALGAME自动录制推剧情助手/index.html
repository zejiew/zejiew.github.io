Galgame 自动录制助手

检测 galgame 剧情在推进还是已经停下，自动控制 OBS 开始/停止录制。
可选「自动推进」：替你按键推进剧情，遇到选项自动停手。

界面走天蓝渐变 + 二次元风格：卡片式分区、胶囊按钮、圆形头像，右上角一眼看到当前是待机还是录制中。

仓库：https://github.com/zejiew/galgame-seeing

零、直接用 exe（不想装 Python 的话）

双击 release\GalgameAutoRec.exe 即可，无需安装 Python。

  • 目录里 GalgameAutoRec.exe 是主程序（约 6 MB），
    _internal\ 是它依赖的运行库（约 190 MB），整个文件夹要一起拷走，不能只拿 exe
  • 首次运行会在 exe 同目录生成 config.yaml 和 recordings\
  • 想确认环境是否就绪：命令行执行 GalgameAutoRec.exe selfcheck，
    结果会写到同目录的 selfcheck.txt 并自动打开

自己重新打包：

打包脚本已经处理了两件容易踩的事：rapidocr 的 onnx 模型是数据文件必须显式带上；
环境里装着的 paddle / torch / PySide6 等无关大包要排除掉（否则产物会从 190 MB 涨到 3 GB）。

一、先决条件（装 Python 跑源码时看）

1. OBS 版本

你的 OBS 怎么用 说明
28 及以上 直接可用 内建 obs-websocket 5.x，功能最全
27 装插件 或 用热键 装 obs-websocket 4.9.1 插件（本目录有安装脚本）；或改用「热键」控制方式，什么都不用装

OBS 28+ 体验最好：程序能自动拿到文件名、读录制时长。

下载：https://obsproject.com/download

2. Python 依赖（仅源码运行需要）

  • numpy / Pillow — 截图与图像比对
  • pywin32 — 窗口枚举与定位
  • rapidocr-onnxruntime — 本地 OCR（纯 CPU、离线、无需联网）
  • websocket-client — 连 OBS
  • tkinter — 图形界面（Python 自带）

跑一次自检确认：

二、快速开始

步骤：

  1. 启动 OBS，确认它已经配好一个能录到游戏的场景
    （窗口捕获 / 游戏捕获 / 显示器捕获都行）
  2. OBS 里开 WebSocket：工具 → WebSocket 服务器设置 → 勾选「启用」
    • OBS 28+ 默认已开，端口 4455
    • OBS 27 装插件后默认端口是 4444（本程序会自动识别，不用手改）
  3. 打开本程序 → 「刷新列表」→ 选中游戏窗口
  4. 点「开始监控」
  5. 正常玩。剧情推进时自动录，剧情停下超过设定秒数自动停

第一次用建议做的两件事

  • 点 「自动识别对话框」：让程序自己找到台词框位置（比全窗口比对准得多）
  • 点 「在这块区域上试识别一次」：确认 OCR 能读到当前台词

三、它是怎么判断「剧情结束」的

只看一个信号：有没有出现新台词。

道理很简单——galgame 的剧情推进就是台词在换。停止判定用「多久没有新台词」，
比盯画面变化可靠得多（动态背景、Live2D 呼吸、UI 动画会一直在动，
用画面变化当依据会永远不停录）。

具体做法：

  1. 每 0.6 秒截一次台词框（可调）

  2. 像素没变化就跳过 OCR，省 CPU

  3. 有变化才 OCR，拿到当前这句台词

  4. 跟上一句做相似度比较（不是字符串相等）：

    • 相似度高 → 还是同一句（打字机在逐字显示），不算推进
    • 相似度低 → 换嘴了，刷新「最后推进时间」

  5. 当前时间 - 最后推进时间 ≥ 结束判定秒数 → 停录

内置的几个保护

保护 作用
打字机识别 同一句越写越长不算新台词，否则一句 20 字的台词会被数成十几次推进
遮挡检测 游戏被浏览器/聊天窗盖住时冻结计时，不会把外面的文字当剧情
开录宽限 刚开录的前 N 秒不判结束（片头、加载中）
最短保留 太短的录像自动删掉（误触发时不会留一堆垃圾）
单段上限 防止忘关录一整天
非游戏文字过滤 万一把 IDE/浏览器的字读进来，会被识别成「不像台词」而丢弃

四、自动推进（可选，默认关闭）

打开后程序会替你在「台词播完、停住等输入」时按一下推进键，
可以挂机把一条线读完。

三条安全规则：

  1. 只在游戏窗口在前台时才按键。切出去看视频/聊天时一下都不按，
    切回游戏自动继续。
  2. 遇到选项自动停手。选项是玩家该拿主意的地方，替你点会毁存档。
    识别方式：画面中部出现 2~4 行短文字、竖直排列（不在对话框里）。
  3. 连续按了没反应就停。说明可能卡在选项/小游戏/等特殊输入上。

设置项：

项 默认 说明
方式 key key=按键 / mouse=点鼠标 / both
按键 space 多数 galgame 用 space 或 enter
台词后等待 2.5 秒 这句显示完多久才按，别打断打字机
最小间隔 1.2 秒 两次按键之间至少隔多久
遇到选项停手 开 强烈建议保持开启
卡住判定次数 8 按这么多次台词还没变就停

暂停后可以在界面点「恢复推进」继续。

五、如果 OBS 是 27

两条路，任选：

A. 装插件（功能全）

双击 安装WebSocket插件(OBS27).bat（需右键 → 以管理员身份运行）。

装完后启动 OBS → 工具 → WebSocket 服务器设置 → 启用，
记下密码（或取消「启用身份验证」）。回到本程序填上密码即可。

插件默认端口是 4444（不是 4455）。本程序会自动尝试 4444/4455，
连上后还会把实际端口写回配置，不用你手动改。

B. 用热键（不装任何东西）

  1. OBS → 设置 → 热键
  2. 给「开始录制」设一个组合键，比如 Ctrl+Alt+F9
  3. 给「停止录制」设一个组合键，比如 Ctrl+Alt+F10
  4. 本程序 → 「OBS」设置页 → 控制方式选 hotkey，把这两个组合键填进去

热键是 OBS 的全局热键，程序在后台发按键就能触发。
代价是拿不到文件名（程序会扫描录制目录里的新文件来补）。

六、参数怎么调

录得太碎（一个场景被切成好几段）

  • 调大「结束判定(秒)」（默认 120）：剧情里常有长时间没台词的过场
  • 调小「最短保留」，避免中间段被删

该停不停（一直录）

  • 确认「必须有台词才算剧情开始」开着
  • 点「自动识别对话框」重新定位台词区域
  • 调大「变化阈值」，让画面小的抖动不触发 OCR

该录不录（迟迟不开录）

  • 调小「结束判定」和「开录宽限」
  • 或把开始条件改成「画面一动就开」
  • 确认 OCR 能读到字（用「试识别一次」验证）

CPU 占用高

  • 调大「采样间隔」到 1.0~1.5 秒
  • OCR 只在画面变化时才跑，不需要关

八、常见问题

Q: 提示「连接 OBS 失败」

  1. OBS 在运行吗？
  2. OBS 27 是否装了 WebSocket 插件？
  3. 端口对不对？（OBS 27 插件是 4444，28+ 是 4455，程序会自动试）
  4. 密码是否与 OBS 里一致？

Q: 连上了但录不出文件
OBS 里要有能录到画面的场景（至少一个捕获源）。本程序只负责「按快门」，
不管 OBS 内部怎么配。

Q: 录出来是黑屏
OBS 里换「游戏捕获」或「窗口捕获」，显示器捕获在独占全屏下可能黑屏。

Q: 自动推进按了没反应

  1. 「试按一次」验证按键是否有效
  2. 游戏窗口必须在前台（程序不会在后台窗口上按键）
  3. 换个键试试（有的游戏认 enter，有的认 space）
  4. 有的游戏需要点鼠标，把方式改成 mouse

Q: 自动推进把选项点掉了
这个不该发生——检查「遇到选项自动停手」是否开着。
如果确实误判，把「卡住判定次数」调小（比如 4）。

Q: 中文乱码 / 界面字体难看
需要系统里有微软雅黑（Windows 自带）。

Q: 想换界面配色 / 换头像
界面风格集中在 galrec/ui_theme.py 顶部那组颜色常量里，改完重启即可。
右上角的圆形头像读的是 galrec/assets/logo.jpg，直接换这张图就行，代码不用动
（打包时会自动带上，见 build_exe.py 的 --add-data）。

十、测试情况

测试 内容 结果
selfcheck 依赖、OCR、窗口、OBS、目录（源码与 exe 各自验证） 通过
test_obs_protocol v5/v4 握手、认证、录制控制、错误密码拒绝、热键解析、台词过滤 全部通过
test_advance 选项识别、真发按键、选项停手、前台保护、卡住检测 全部通过
simulate 假游戏窗口喂台词，验证自动开录/停录、遮挡干扰 通过
e2e_obs_v5 真 OBS 33（便携版）连接、录制、文件产出、Controller 全链路 核心链路通过
exe 自检 打包后在 exe 内跑 selfcheck：OCR 模型加载 0.5s、tkinter、窗口枚举 通过

说明：便携版 OBS 在无桌面会话下手动配源时录制输出不稳定，与程序逻辑无关；
在正常桌面环境用正式 OBS 时录制正常（已实测产出 2.2 MB / 3 秒素材）。

已知限制

  • 结束判定依赖「台词换句」。纯过场 CG（长时间无台词）会被当成剧情结束而停录，
    这是设计取舍；需要避开时把「结束判定」调大（如 300 秒）
  • OCR 需要游戏有可读文字。全语音无字幕的作品只能靠「画面一动就开」模式
  • 自动推进默认关闭，且不做选项选择（遇选项即停手）
